# crux-execute

Execute an engineering plan with guided subagent coordination, progress tracking, and completion verification.

**Repository**: [github.com/zotoio/CRUX-Compress](https://github.com/zotoio/CRUX-Compress)

## Usage

```
/crux-execute                                          - Execute the most recent plan in plans/
/crux-execute plans/20260403-memory-system              - Execute a specific plan by directory
/crux-execute plans/20260403-memory-system/plan-memory-system-20260403.md  - Execute by index file path
/crux-execute --resume                                  - Resume an interrupted execution
```

## Instructions

When this command is invoked, spawn a `crux-planner` subagent to execute an engineering plan. The planner uses the `crux-execute-plan` skill to coordinate the work.

### Argument Handling

- **No arguments**: Find the most recently modified plan directory in `plans/` and execute it
- **Directory path**: Execute the plan in the specified directory (finds the `plan-*.md` index file automatically)
- **File path**: Execute the plan using the specified index file directly
- **`--resume`**: Resume an interrupted execution — the planner reads the plan index to determine which subtasks are already complete and continues from the next incomplete one

Pass `$ARGUMENTS` to the subagent as the plan path (or `--resume` flag).

### What Happens

1. **Load & Validate**: The planner reads the plan index and validates the Subtask Manifest — confirms all files exist, agent assignments match metadata, and dependencies are correctly ordered
2. **Confirm**: Presents the manifest as an execution summary (phases, subtask count, agent assignments per subtask) and waits for user approval
3. **Execute**: For each phase in order:
   - Spawns the **exact subagent listed in the manifest** for each subtask (up to 4 in parallel) — agent assignments are never overridden
   - Provides each subagent with full subtask context (objectives, deliverables, implementation notes)
   - Each subagent **ticks off Deliverables Checklist and Definition of Done items** in the subtask file as work progresses — not all at once at the end
   - Each subagent fills in the Execution Notes section (agent info, work log, files modified)
   - Waits for all phase subtasks to complete before the next phase
4. **Adversarial Verification**: After each subtask completes, a **fresh `integrity-expert`** (not the agent that did the work) independently verifies every deliverable:
   - Resets all checklist items in the subtask file and re-verifies from scratch
   - Inspects each Deliverables Checklist and Definition of Done item — confirms files exist, code compiles, tests are valid
   - Re-ticks only items independently confirmed complete — the subtask file reflects verified state, not self-reported state
   - Flags anything missing or incorrect
   - Returns verdict: Verified / Partial / Failed
5. **Final Verification**: After all subtasks are verified:
   - Runs the full test suite (`python3 scripts/test.py`)
   - Checks linter errors on all modified files
   - Spawns `integrity-expert` for overall code quality audit
   - Spawns `docs-sync-agent` for documentation updates if trigger files changed
6. **Execution Report**: Writes a persistent report to the plan directory as `execution-report-[feature-name]-[yyyymmdd].md` with per-subtask results, verification outcomes, test/lint status, and files modified
7. **Review**: Presents the execution report and asks for user approval
8. **Complete**: After user approval, marks the plan status as `Completed`

### Execution Safeguards

| Safeguard | Behaviour |
|-----------|-----------|
| **Manifest-driven dispatch** | The subagent for each subtask comes from the manifest's Subagent column — never overridden |
| **Adversarial verification** | Every subtask is verified by a fresh `integrity-expert` that did not execute the work |
| **Dependency enforcement** | Never starts a subtask before its dependencies are complete |
| **Failure handling** | If a subtask fails or verification returns Failed, stops and asks user: retry, skip, or abort |
| **Parallel limit** | Maximum 4 concurrent subagents per batch |
| **No global tests mid-execution** | Individual subtasks run only targeted tests; full suite deferred to final verification |
| **Progress persistence** | Plan index manifest is updated after each subtask — supports `--resume` on interruption |
| **User gates** | Requires user approval before starting and before marking complete |
| **Durable execution report** | Written to plan directory as a persistent audit trail |

### Execution Report

The report is written to the plan directory alongside the index and subtask files:

```
plans/20260403-memory-system/
├── plan-memory-system-20260403.md
├── subtask-01-memory-system-foundation-20260403.md
├── ...
└── execution-report-memory-system-20260403.md    ← generated by /crux-execute
```
